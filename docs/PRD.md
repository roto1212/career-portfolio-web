# PRD — career-portfolio-web

> 구현 후 정리한 문서입니다. 당시 결정과 이유를 남겨 두는 것이 목적입니다.
> 작성일: 2026-11-04 · 작성자: 선대범

## 1. 배경과 문제

- 이력과 프로젝트 기록이 **Obsidian 마크다운**과 **정적 프로필 사이트**(GitHub Pages)로 나뉘어 있었다.
- 내용을 고칠 때마다 두 곳을 손봐야 했고, 어느 쪽이 최신인지 헷갈렸다.
- 기록을 쌓는 `career-log` 스킬도 Obsidian 전용이라, 공개 사이트로 나가려면 별도 가공이 필요했다.
- 인프런 강의 수강 자료(Next.js 스타터킷)를 보다가, 원본을 Notion 하나로 두고 사이트는 읽기만 하는 구조가 가능하겠다는 힌트를 얻어 시작했다.

## 2. 목표 / 비목표

### 목표

| #   | 목표                                                                           |
| --- | ------------------------------------------------------------------------------ |
| G1  | Notion을 **유일한 원본**으로 둔다. 사이트 수정은 Notion 편집만으로 끝난다.     |
| G2  | **행 단위로 공개 여부를 제어**한다. 공개하지 않은 내용이 사이트에 새지 않는다. |
| G3  | Notion에서 저장한 내용이 사이트에 **빠르게 반영**된다.                         |
| G4  | `career-log` 저장 직후 사이트 갱신까지 **자동**으로 이어진다.                  |
| G5  | 회사 업무와 개인(회사 외) 프로젝트를 **구분해서** 보여준다.                    |
| G6  | 채용 담당자가 한 페이지로 훑고, A4 PDF로 저장할 수 있다.                       |

### 비목표

- 로그인, 댓글, 방문자 분석 등 사용자 계정이 필요한 기능 (인증 없는 읽기 전용 사이트)
- 사이트 안에서의 콘텐츠 편집 (편집은 항상 Notion)
- 프로젝트 상세 페이지(`/projects/[slug]`), 다국어, 블로그
- Notion 본문의 전체 렌더링 (STAR 4블록과 수강 이력만 읽는다)

## 3. 사용자

| 사용자            | 하는 일                                           | 필요한 것                               |
| ----------------- | ------------------------------------------------- | --------------------------------------- |
| 방문자(채용 담당) | 한 페이지로 경력·기술·프로젝트를 확인, PDF로 저장 | 빠른 로딩, 읽기 쉬운 구조, 인쇄 품질    |
| 작성자(본인)      | Notion이나 `career-log`로 기록, 공개 여부 결정    | 한 곳에서 편집, 실수로 공개되지 않는 것 |

## 4. 기능 요구사항

### 4.1 데이터 (Notion)

- **FR-1** DB 5개를 둔다: Orgs · Projects · Achievements · Skills · Profile. (스키마는 [`notion-schema.md`](notion-schema.md))
- **FR-2** `Public` 체크박스가 켜진 행만 읽는다. 필터는 **쿼리 단계**에서 강제한다. Profile DB는 1행짜리라 `Public` 속성이 없어 무필터로 읽는다.
- **FR-3** 프로젝트 본문에서 `## S —`, `## T —`, `## A —`, `## R —` 형식의 H2만 STAR로 읽는다. 그 외 제목 아래(예: `## 상세 (비공개 메모)`)는 사이트에 나오지 않는다.
- **FR-4** 스킬 본문의 수강 이력(`[강의명](URL)` 외 2개 형식)을 읽어 수료증 링크로 보여준다. https/http 외 스킴은 버린다.
- **FR-5** `Kind`(work/side)가 비어 있으면 work로 취급한다. side는 변경 이력에 넣지 않는다.

### 4.2 화면

| 경로              | 내용                                                                                    |
| ----------------- | --------------------------------------------------------------------------------------- |
| `/`               | hero(역할·핵심 지표) → skills → changelog → pinned → side(데이터가 있을 때만) → contact |
| `/print`          | A4 이력서. `noindex`. 헤더의 `pdf ↓`로 인쇄 화면이 열린다                               |
| `/api/revalidate` | POST 전용. 시크릿이 맞을 때만 캐시를 무효화한다                                         |

- **FR-6** 변경 이력은 `Ver`(`v<조직>.<큰 프로젝트>.<작은 프로젝트>`)를 **숫자로 비교**해 내림차순으로 정렬한다. (문자열 정렬은 `v2.13.0`이 `v2.2.0`보다 앞서는 오류가 생긴다)
- **FR-7** pinned 카드를 누르면 STAR 패널이 펼쳐진다(접근성: `aria-expanded`, `aria-controls`). side 카드는 시작 계기(`Origin`)를 한 줄로 보여준다.
- **FR-8** 상단 내비게이션은 scroll spy로 현재 섹션을 표시한다. side 링크는 side 데이터가 있을 때만 나온다.
- **FR-9** 다크 모드(시스템 설정 기본)와 `prefers-reduced-motion`을 지원한다. 이메일 복사 버튼을 둔다.
- **FR-10** OG 메타와 이미지를 제공한다. 사이트 주소는 서버 전용 `APP_URL`로 지정한다.

### 4.3 갱신

- **FR-11** 기본은 1시간 ISR 캐시(`revalidate = 3600`, 태그 `portfolio`).
- **FR-12** `POST /api/revalidate`에 `Authorization: Bearer <REVALIDATE_SECRET>`를 보내면 `portfolio` 태그를 무효화한다. 실패하면 401, GET은 405.
- **FR-13** 개발 환경(`NODE_ENV=development`)은 캐시를 쓰지 않는다.
- **FR-14** `career-log` 스킬은 Notion 저장·검증 뒤 갱신 스크립트를 실행하고, 결과(HTTP 코드)를 보고한다. 설정 파일이 없으면 건너뛰고, 실패해도 저장은 유지한다.

## 5. 비기능 요구사항

### 보안

- **NFR-1** 토큰·시크릿은 서버 전용 환경변수다. `NEXT_PUBLIC_` 접두사를 쓰지 않는다. (`NOTION_TOKEN`, `*_DS_ID`, `REVALIDATE_SECRET`, `APP_URL`)
- **NFR-2** 환경변수는 `src/lib/env.ts`에서 Zod로 검증한다. `REVALIDATE_SECRET`은 16자 이상이다.
- **NFR-3** 시크릿 비교는 `timingSafeEqual`을 쓴다.
- **NFR-4** 본문은 평문으로 변환해 React 이스케이프에 맡긴다. `dangerouslySetInnerHTML`을 쓰지 않는다.
- **NFR-5** Notion 연결은 읽기 전용 Internal Integration이며, 부모 페이지 한 곳에만 연결한다.
- **NFR-6** `career-log`의 갱신 시크릿은 권한 600 파일에만 두고, 프로세스 목록에 보이지 않게 curl 설정을 stdin으로 넘긴다.
- **NFR-7** 외부 공개 문구 기준: 회사·제품 실명은 허용, 인명·직책 호칭과 사내 운영 정보, 보안망 상세는 금지한다. (`career-log` 스킬이 작성 시 강제)

### 성능·품질

- **NFR-8** 페이지는 정적 생성 + ISR이다. 방문자 요청마다 Notion을 호출하지 않는다.
- **NFR-9** Notion API 호출은 동시 3건으로 제한한다(평균 3 req/s 제한 대응).
- **NFR-10** `pnpm check-all`(타입·ESLint·Prettier)과 `pnpm build`가 통과해야 한다. pre-commit(Husky + lint-staged)로 강제한다.
- **NFR-11** 의존성 취약점은 정기적으로 `pnpm audit --prod`로 점검한다. (Vercel이 취약 버전 배포를 차단한다)

## 6. 아키텍처 요약

```
Notion DB 5개 ──(SDK, Public=true만)──▶ Next.js 15 (RSC, unstable_cache) ──▶ Vercel
        ▲                                     ▲
   career-log 스킬                    POST /api/revalidate ◀── revalidate.sh
```

- 기술 스택: Next.js 15.5.29 · React 19 · TypeScript · Tailwind CSS v4 · shadcn/ui · `@notionhq/client` v5 · Zod · pnpm · Vercel
- 핵심 모듈: `src/lib/notion/{queries,mappers,markdown,props}.ts`, `src/lib/career-format.ts`, `src/app/api/revalidate/route.ts`
- 디자인: 기존 프로필 사이트의 토큰(색·간격·도트 그리드)을 이식하고, Pretendard를 self-host한다.

## 7. 주요 결정과 이유

| 결정                                | 이유                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------- |
| Notion을 CMS로 사용                 | 편집 UI를 직접 만들지 않고, 행 단위 공개 제어와 관계형 데이터를 그대로 쓸 수 있다.          |
| 공개 필터를 쿼리 단계에서 강제      | 화면에서 숨기는 방식은 실수로 노출될 수 있다. 서버가 읽지 않으면 새지 않는다.               |
| STAR 파서를 정확한 제목 형식만 인정 | 같은 페이지 안에 비공개 메모를 두기 위해서다. 허용 목록 방식이라 새 제목이 생겨도 안전하다. |
| ISR 1시간 + 온디맨드 무효화         | Notion API 호출 제한(평균 3 req/s)을 피하면서, 필요할 때 즉시 반영한다.                     |
| 개인 워크스페이스 MCP만 사용        | 회사 워크스페이스에 개인 이직 정보가 섞이지 않게 한다.                                      |
| `Kind`로 work/side 분리             | 회사 버전 체계(`Ver`)와 개인 프로젝트를 섞지 않는다.                                        |
| 서버 전용 `APP_URL`                 | `NEXT_PUBLIC_` 값은 브라우저에 노출된다. Vercel도 이 경우 경고한다.                         |
| 상세 페이지·블로그는 제외           | 채용 담당이 한 페이지로 훑는 용도에 집중하고, 유지 비용을 줄인다.                           |
